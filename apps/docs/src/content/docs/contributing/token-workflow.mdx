피그마 파일은 읽기만 합니다. 사람이 하는 일은 피그마 원문을 교체하는 데까지이고, 정규화와 산출물 생성은 스크립트가 맡습니다. CSS를 손으로 고치면 피그마와 어긋나도 알아챌 방법이 없기 때문입니다.

## 순서

1. 디자이너가 피그마를 고치고 변경 내용(무엇을, 왜, 영향 화면)을 알립니다.
2. 원문을 교체하고 `figma/manifest.json`의 sha256을 갱신합니다.
   - 변수: Variables 패널에서 `Color`, `Token` 컬렉션을 Export modes로 받아 `figma/export/`에 같은 이름으로 덮어씁니다.
   - 텍스트 스타일: 피그마 MCP `get_variable_defs`(노드 2268:1706) 결과를 `figma/mcp/`에 그대로 저장합니다.
3. 아래 명령을 차례로 실행합니다.
4. [피그마 정규화 리포트](/contributing/figma-normalization/)의 이름 변경과 경고를 디자인 팀과 확인합니다.

```bash
pnpm figma:inspect      # export 형식, 개수, 참조 확인
pnpm tokens:normalize   # figma/ 원문 → tokens/*.json, 리포트
pnpm tokens:build       # tokens/*.json → src/generated/*
pnpm tokens:check       # 다시 만든 결과와 저장된 파일 비교
pnpm test
```

## 자동으로 막는 것

| 상황                                  | 결과                 |
| ------------------------------------- | -------------------- |
| 원문 파일이 manifest의 해시와 다름    | 테스트 실패          |
| 풀리지 않는 참조, srgb가 아닌 색      | `figma:inspect` 실패 |
| 두 변수가 같은 코드 이름이 됨         | 정규화 실패          |
| 규칙이 없는 새 변수, 입력에 없는 규칙 | 정규화 실패          |
| 생성물을 손으로 고침                  | `tokens:check` 실패  |

## 규칙을 바꾸는 곳

이름 변경, 제외, 디자인 팀 확인 질문은 `packages/design-tokens/scripts/normalize/rules.ts`에서 바꿉니다. 그리드와 레이아웃 값은 피그마 변수가 아니라 문서 프레임에 있어서 `tokens/layout.json`을 손으로 고칩니다.
