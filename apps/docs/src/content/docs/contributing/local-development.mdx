## 시작하기

Node 22.12 이상이 필요합니다. pnpm 버전은 루트 `package.json`의 `packageManager`가 정하므로 corepack을 켜 둡니다.

```bash
corepack enable
pnpm install
pnpm build:packages
pnpm docs:dev
```

문서 개발 서버는 `http://localhost:5174/umc-product-design-system/`에 뜹니다. 배포 주소와 같은 경로를 쓰므로 `localhost:5174/`로 열면 404가 나옵니다.

문서 사이트는 워크스페이스 패키지의 `dist`를 불러옵니다. 컴포넌트, 토큰, 아이콘 코드를 고치면 `pnpm build:packages`를 다시 돌려야 문서에 반영됩니다.

## 저장소 구조

```
packages/design-tokens   피그마 변수를 CSS 변수, Tailwind, vanilla-extract로
packages/icons           피그마 SVG를 React 아이콘 컴포넌트로
packages/react           Base UI 기반 컴포넌트와 미리 빌드한 CSS
apps/docs                Astro Starlight 문서 사이트
scripts                  배포물 검사와 소비자 스모크 테스트
.changeset               다음 배포에 들어갈 변경 기록
.github/workflows        CI, 버전 PR, 패키지 배포, 문서 배포
```

## 검사 명령

PR을 열면 CI가 아래 명령을 모두 돌립니다. 패키지 코드를 고쳤다면 적어도 `test`, `typecheck`, `format:check`는 PR 전에 로컬에서 돌립니다.

| 명령                              | 하는 일                                                    |
| --------------------------------- | ---------------------------------------------------------- |
| `pnpm test`                       | 세 패키지의 Vitest 테스트                                  |
| `pnpm typecheck`                  | 패키지와 문서의 타입 검사                                  |
| `pnpm format:check`               | Prettier 형식 검사. 고칠 때는 `pnpm format`                |
| `pnpm tokens:check`               | 피그마 원문으로 다시 만든 토큰이 커밋된 결과와 같은지 비교 |
| `pnpm icons:check`                | 아이콘 생성물이 원문과 같은지 비교                         |
| `pnpm lint:package`               | 배포할 tarball을 publint와 attw로 검사                     |
| `node scripts/smoke-consumer.mjs` | tarball을 새 Vite 앱에 설치해 타입 검사, 빌드, 서버 렌더링 |
| `pnpm docs:build`                 | 문서 빌드                                                  |
| `pnpm docs:variants`              | 피그마 변형이 문서에 빠짐없이 한 번씩 그려졌는지 확인      |
| `pnpm docs:links`                 | 빌드한 문서의 내부 링크가 모두 열리는지 확인               |

## 브랜치와 PR

- 기본 브랜치는 develop입니다. 작업 브랜치를 develop에서 만들고 PR도 develop으로 보냅니다.
- main은 배포 브랜치입니다. develop을 main에 병합하면 패키지와 문서가 배포됩니다.
- 앱이 받는 패키지가 바뀌는 PR에는 changeset을 넣습니다. 문서, 검사, 저장소 설정만 바꾸는 PR에는 넣지 않습니다. 쓰는 방법은 [배포 절차](../release-process/)에 있습니다.

## 배포 전에 다른 앱에서 써 보기

배포하지 않은 변경을 앱에서 시험하려면 스모크 테스트의 작업 폴더를 남깁니다.

```bash
node scripts/smoke-consumer.mjs --keep
```

출력에 나온 폴더의 `packs/`에 tarball 세 개가 있습니다. 시험할 앱의 `package.json`에서 세 패키지를 tarball로 바꾸고 `pnpm.overrides`에도 같은 경로를 적은 뒤 `pnpm install`을 실행합니다. overrides가 없으면 react 패키지가 토큰과 아이콘을 레지스트리에서 받으려고 합니다.

```json
{
  "pnpm": {
    "overrides": {
      "@umc-product/design-tokens": "file:<폴더>/packs/umc-product-design-tokens-0.1.0.tgz",
      "@umc-product/icons": "file:<폴더>/packs/umc-product-icons-0.1.0.tgz",
      "@umc-product/react": "file:<폴더>/packs/umc-product-react-0.1.0.tgz"
    }
  }
}
```

시험이 끝나면 앱의 `package.json`과 lockfile을 되돌립니다.
