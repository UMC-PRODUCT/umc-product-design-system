디자인 시스템은 패키지 세 개로 나뉩니다. 세 패키지는 항상 같은 버전으로 함께 배포합니다.

| 패키지                       | 내용                                            | 의존                   |
| ---------------------------- | ----------------------------------------------- | ---------------------- |
| `@umc-product/design-tokens` | 피그마 토큰을 CSS 변수와 Tailwind v4 유틸리티로 | 없음                   |
| `@umc-product/icons`         | 아이콘 65종, 픽토그램 11종, 로고 React 컴포넌트 | React 19               |
| `@umc-product/react`         | Base UI 위에 만든 컴포넌트와 미리 빌드한 CSS    | React 19, 위 두 패키지 |

모든 산출물은 같은 `--umc-*` CSS 변수를 가리키기 때문에, 앱이 어떤 스타일 도구를 쓰든 같은 값이 나옵니다.

## 처음 한 번: 토큰과 레지스트리

패키지는 GitHub Packages에 비공개로 올라가 있습니다. UMC-PRODUCT 조직 멤버라면 설치할 수 있지만, 공개 npm과 달리 GitHub 토큰이 있어야 합니다.

<Steps>

1. GitHub에서 **Settings → Developer settings → Personal access tokens → Tokens (classic)** 으로 가서 토큰을 만듭니다. 권한은 `read:packages` 하나면 됩니다. GitHub Packages는 classic 토큰만 받습니다.

2. 내 컴퓨터의 `~/.npmrc`(사용자 폴더)에 토큰을 적습니다. 저장소에는 올리지 않습니다.

   ```ini
   //npm.pkg.github.com/:_authToken=ghp_여기에_토큰
   ```

3. 앱 저장소 루트의 `.npmrc`에 레지스트리를 적고 커밋합니다. 토큰도, `${NODE_AUTH_TOKEN}` 같은 변수도 넣지 않습니다. 변수가 비어 있으면 pnpm이 파일을 통째로 무시해 이 줄까지 사라집니다.

   ```ini
   @umc-product:registry=https://npm.pkg.github.com
   ```

</Steps>

## 설치

```bash
pnpm add @umc-product/react @umc-product/icons @umc-product/design-tokens
```

토큰만 쓰는 앱은 `@umc-product/design-tokens` 하나만 설치합니다.

0.x 동안에는 minor가 깨지는 변경입니다. `^0.1.0`은 0.1.x만 받고 0.2.0은 받지 않으니, 새 minor는 [변경 기록](../../releases/changelog/)을 보고 직접 올립니다. 자세한 기준은 [버전 정책](../../releases/versioning/)에 있습니다.

## CSS 불러오기

컴포넌트를 쓰는 앱은 `@umc-product/react/styles.css` 하나를 불러옵니다. 이 파일이 `fonts.css`, `base.css`, 헤더 홈 링크의 Orbitron 글꼴을 함께 불러오므로 토큰 CSS를 따로 넣지 않아도 됩니다. Tailwind 유틸리티로 토큰을 쓰려면 `tailwind.css`를 더합니다.

```css
@import "tailwindcss";
@import "@umc-product/react/styles.css";
@import "@umc-product/design-tokens/tailwind.css";
```

토큰만 쓰는 앱은 아래처럼 불러옵니다. 순서가 중요합니다.

```css
@import "tailwindcss";
@import "@umc-product/design-tokens/fonts.css";
@import "@umc-product/design-tokens/base.css";
@import "@umc-product/design-tokens/tailwind.css";
```

이 CSS는 앱 전역 스타일 파일에 둡니다. Vite 앱은 `main.tsx`가 불러오는 CSS 파일(예: `src/index.css`), Next.js App Router는 `app/layout.tsx`가 불러오는 `app/globals.css`입니다. CSS 안의 `@import`를 패키지 이름으로 풀어야 하므로 번들러를 거쳐야 하고, HTML의 `<link>`로 바로 불러올 수는 없습니다.

`base.css`를 빠뜨리면 유틸리티가 빈 변수를 참조해, 오류 없이 스타일만 사라집니다.

## 컴포넌트와 아이콘 쓰기

```tsx
import { SearchIcon } from "@umc-product/icons"
import { Button, TextField } from "@umc-product/react"

<TextField label="이름" placeholder="이름을 입력하세요" />
<Button size="md" leadingIcon={<SearchIcon />}>
  검색
</Button>
```

- **스타일 덮어쓰기**: 컴포넌트 스타일은 `@layer components`에 있습니다. Tailwind 유틸리티(`utilities` 레이어)와 레이어 밖에 선언한 앱 CSS가 모두 컴포넌트보다 우선하므로 `className`으로 덮어쓸 수 있습니다. `styles.css`를 Tailwind보다 먼저 불러와도 레이어 순서는 같습니다.
- **서버 컴포넌트**: 상호작용이 있는 컴포넌트는 `"use client"`를 선언해 두었습니다. Next.js App Router의 서버 컴포넌트 안에 그대로 놓을 수 있습니다.
- **라우터 링크**: `Header`, `SideNavigation`, `PageHeader`가 그리는 링크는 [LinkProvider](../../components/shell/link-provider/)로 앱의 라우터 링크를 등록해 바꿉니다.
- **아이콘 색**: 아이콘은 `currentColor`를 쓰므로 글자색을 따릅니다. 픽토그램은 자기 색을 갖고 있어서 상태 색을 따르게 하려면 `color="currentColor"`를 넘깁니다.

## 앱의 CI와 배포 환경

로컬과 마찬가지로 CI와 배포 서버도 설치할 때 토큰이 필요합니다.

### GitHub Actions

<Steps>

1. 디자인 시스템 저장소 관리자가 GitHub의 조직 **Packages** 탭에서 세 패키지를 하나씩 열고, **Package settings → Manage Actions access**에 앱 저장소를 읽기 권한으로 더합니다. 이렇게 하면 앱 워크플로의 `GITHUB_TOKEN`으로 설치할 수 있습니다.

2. 앱 워크플로에 권한과 레지스트리를 설정합니다. `NODE_AUTH_TOKEN`은 job 전체에 둡니다.

   ```yaml
   jobs:
     build:
       runs-on: ubuntu-latest
       permissions:
         contents: read
         packages: read
       env:
         NODE_AUTH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
       steps:
         - uses: actions/checkout@v7
         - uses: pnpm/action-setup@v6
         - uses: actions/setup-node@v7
           with:
             node-version: 22
             cache: pnpm
             registry-url: https://npm.pkg.github.com
             scope: "@umc-product"
         - run: pnpm install --frozen-lockfile
   ```

</Steps>

setup-node가 만드는 `.npmrc`는 토큰 자리에 `${NODE_AUTH_TOKEN}`을 씁니다. pnpm은 비어 있는 변수가 있는 `.npmrc`를 통째로 무시하므로, 변수를 설치 단계에만 두면 다른 단계마다 경고가 나옵니다.

### AWS Amplify

Amplify 빌드는 GitHub 밖에서 돌아서 `GITHUB_TOKEN`을 쓸 수 없습니다. `read:packages` classic 토큰을 Amplify 환경 변수(예: `UMC_PACKAGES_TOKEN`)에 넣고, 설치 전에 `.npmrc`에 적습니다.

```yaml
frontend:
  phases:
    preBuild:
      commands:
        - printf '\n//npm.pkg.github.com/:_authToken=%s\n' "$UMC_PACKAGES_TOKEN" >> .npmrc
        - pnpm install --frozen-lockfile
```

앞에 줄바꿈을 넣는 이유는 저장소의 `.npmrc`가 줄바꿈 없이 끝나면 토큰 줄이 스코프 줄 뒤에 붙어 버리기 때문입니다.

<Aside type="caution" title="개인 토큰을 넣지 마세요">
  개인 계정 토큰을 넣으면 그 사람이 조직을 떠나거나 기수가 바뀔 때 모든 빌드가
  멈춥니다. 조직의 공용 계정에서 만든 토큰을 쓰고, 만료일을 정해 갱신 담당자를
  둡니다.
</Aside>

## Vite 빌드 경고 끄기

Vite는 패키지 안의 `"use client"`를 무시한다는 경고(`MODULE_LEVEL_DIRECTIVE`)를 컴포넌트마다 냅니다. 동작에는 영향이 없습니다. 경고를 끄려면 `vite.config.ts`에 더합니다.

```ts
export default defineConfig({
  build: {
    rollupOptions: {
      onwarn(warning, warn) {
        if (warning.code === "MODULE_LEVEL_DIRECTIVE") return
        warn(warning)
      },
    },
  },
})
```

## 지원 환경

- React 19(`react`, `react-dom`은 peer 의존성)
- ESM 전용입니다. CommonJS에서는 `import()`로 불러옵니다. Jest를 쓰면 ESM 설정이 필요하니 Vitest를 권합니다
- 브라우저는 Tailwind v4와 같은 기준입니다(Chrome·Edge 111, Safari 16.4, Firefox 128 이상). 컴포넌트 CSS가 `:has()`, `@layer`, CSS `translate` 속성을 씁니다
- Windows 고대비 테마처럼 강제 색 모드(`forced-colors: active`)에서는 그림자와 배경색이 지워집니다. 컴포넌트는 이때 경계와 선택 상태를 시스템 색(CanvasText, Highlight)으로 다시 그립니다

## 주의할 점

- **Tailwind 기본 팔레트를 지웁니다.** `bg-teal-500`은 피그마 `Teal-500`이고, 피그마에 없는 기본 색 클래스는 생기지 않습니다. 앱 색을 더하는 방법과 import 순서는 [Tailwind CSS에서 쓰기](../tailwind/#기본-팔레트와-앱-색)에 있습니다.
- **토큰 덮어쓰기는 레이어 밖에서 합니다.** 토큰은 `@layer umc.tokens`에 선언되어 있어서 `@layer base` 안에서 `--umc-*`를 바꾸면 적용되지 않습니다.
- **브레이크포인트 토큰은 아직 없습니다.** 디자인 팀과 경계값을 정할 때까지 앱의 기존 브레이크포인트를 씁니다.

설치하다 막히면 [문제 해결](../troubleshooting/)을 보세요.
