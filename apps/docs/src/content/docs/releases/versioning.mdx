## 세 패키지는 같은 버전

`@umc-product/design-tokens`, `@umc-product/icons`, `@umc-product/react`는 언제나 같은 번호로 함께 올라갑니다. 토큰만 바뀌어도 세 패키지가 모두 새 버전이 됩니다. 앱도 세 패키지를 같은 버전으로 맞춥니다.

## 0.x 동안의 규칙

0.x에서는 깨지는 변경과 추가를 minor로, 수정과 피그마 값 동기화를 patch로 올립니다.

| 올리는 자리           | 언제                                                                 | 예                                                                                                                                                                                                           |
| --------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| minor (0.1.0 → 0.2.0) | 앱 코드를 고쳐야 할 수 있는 변경, 앱이 쓸 수 있는 것이 늘어나는 변경 | 깨지는 변경: 토큰, CSS 변수, 유틸리티 클래스의 이름 변경과 삭제. 컴포넌트와 prop의 삭제, 이름 변경, 타입 축소. 기본값 변경. export 경로 변경. peer 의존성 범위 변경. 추가: 컴포넌트, prop, 토큰, 아이콘 추가 |
| patch (0.1.0 → 0.1.1) | 앱 코드도, 앱이 쓸 수 있는 것도 그대로인 변경                        | 버그 수정. 이름은 그대로 두고 피그마 값만 맞추는 동기화                                                                                                                                                      |

추가를 minor로 올리는 이유는 두 가지입니다. 먼저 아래 1.0.0 이후 규칙과 같아서, 1.0.0이 되어도 깨지는 변경의 자리만 major로 옮기면 됩니다. 컴포넌트 CSS는 `styles.css` 하나로 묶여 모든 앱에 들어가므로, 컴포넌트 하나를 더해도 앱이 받는 CSS가 늘어납니다. patch는 받아도 늘어나는 것이 없게 둡니다.

minor 안에 깨지는 변경이 있는지는 변경 기록 항목의 **깨지는 변경** 표시로 가립니다. 저장소 README의 릴리스 토글은 요약 줄에 깨지는 변경 건수를 보여 주고, GitHub Release의 "개발자가 올릴 때 할 일"에는 깨지는 변경의 대응표 전문이 실립니다.

앱의 `^0.1.0` 범위는 0.1.x만 받습니다. 범위 안의 patch와 범위를 넘는 minor는 올리는 명령이 다릅니다.

```bash
pnpm up "@umc-product/*"
pnpm up "@umc-product/*" --latest
```

위 명령은 0.1.x 안에서 최신 patch로 올립니다. 아래 명령은 범위를 넘어 최신 minor까지 올리므로 [변경 기록](../changelog/)을 먼저 읽습니다. 새 컴포넌트나 prop이 필요할 때도 아래 명령을 씁니다.

### 계약에 들어가는 것

버전 규칙은 아래에만 적용합니다.

- 패키지가 내보내는 컴포넌트, 훅, 타입, 아이콘, 토큰 배열
- 토큰 CSS 변수(`--umc-color-…`, `--umc-typography-…` 등), Tailwind 유틸리티 클래스
- 컴포넌트 props와 기본값, 렌더링하는 역할(role)과 접근 가능한 이름

컴포넌트 클래스(`umc-button`, `umc-button__label`), 컴포넌트 전용 변수(`--umc-button-bg`), DOM 구조, `data-*` 속성은 계약이 아닙니다. patch에서도 바뀔 수 있으니 앱 CSS의 선택자로 쓰지 않습니다. 모양은 `className`으로 덮어씁니다.

### 화면이 바뀌는 patch

피그마 값을 맞추느라 색이나 크기만 바뀌는 변경은 patch입니다. 이름이 그대로라 코드는 깨지지 않지만 화면은 달라집니다. 이런 변경은 변경 기록 항목을 **화면 변화**로 시작하고 바뀌기 전과 후의 값을 적습니다.

앱은 lockfile이 버전을 고정하므로 화면은 의존성을 올릴 때만 바뀝니다. 올린 뒤 변경 기록의 화면 변화 항목에 나온 화면을 확인합니다.

## 깨지는 변경을 알리는 방법

- changeset 본문에 옛 이름과 새 이름의 대응표를 넣습니다. 피그마 동기화로 이름이 여럿 바뀌면 대응표 전체를 싣습니다.
- 앱에서 옛 이름을 찾는 검색 명령(`rg`)을 함께 적습니다.
- 0.x에서는 옛 이름을 별칭으로 남기지 않습니다. 대응표로 한 번에 바꿀 수 있게 하는 데 집중합니다.

changeset을 쓰는 방법은 저장소의 [배포 절차](https://github.com/UMC-PRODUCT/umc-product-design-system/blob/develop/contributing/release-process.md)에 있습니다.

## 1.0.0으로 가는 조건

- 브레이크포인트 토큰과 모바일 헤더가 확정됩니다.
- 팀 FE 저장소 한 곳 이상에 적용해 실제 화면에서 검증합니다.
- 한 달 동안 깨지는 변경이 없습니다.

  1.0.0부터는 일반적인 유의적 버전을 따릅니다. major가 깨지는 변경, minor가 추가, patch가 수정입니다.
