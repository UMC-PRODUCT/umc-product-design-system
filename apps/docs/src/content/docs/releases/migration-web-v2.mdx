- 소유자: 웹 파트

## 세 단계로 나누는 이유

web-v2와 디자인 시스템에는 이름은 같고 값이 다른 클래스가 여럿 있습니다. `teal-100`부터 `teal-900`까지, 텍스트 스타일 17개(681회), `shadow-inner-neutral-1`(6회)입니다. Tailwind는 같은 이름의 색과 `@utility`를 나중에 선언한 쪽 값으로 만듭니다. 그래서 DS CSS를 앱 CSS보다 먼저 불러오면 겹치는 이름은 앱 값을 유지합니다(Tailwind 4.3.3에서 확인).

이 성질을 이용해 도입을 세 단계로 나눕니다.

1. **들이기**: DS를 앱 CSS 앞에 불러옵니다. 화면은 몇 곳을 빼면 그대로입니다.
2. **옮기기**: 화면 단위로 DS 클래스와 컴포넌트로 바꾸고, 값이 달라지는 곳은 디자인 팀과 확인합니다.
3. **지우기**: 앱이 따로 정의한 색, 텍스트 스타일, 그림자를 지웁니다.

## 1단계: 화면을 그대로 두고 들이기

<Steps>

1. **설치**: [설치와 불러오기](../../getting-started/installation/)를 따라 `.npmrc`, Amplify 환경 변수, GitHub Actions 권한을 설정하고 세 패키지를 설치합니다. 디자인 시스템 관리자에게 세 패키지의 Manage Actions access에 web-v2를 더해 달라고 요청합니다. `tailwindcss`와 `@tailwindcss/vite`는 디자인 시스템이 검사하는 4.3 이상으로 함께 올립니다.

2. **tailwind-merge v3**: `pnpm add tailwind-merge@^3`으로 올리고 `src/shared/lib/utils.ts`의 등록을 고칩니다. 지금 설정에는 앱 텍스트 스타일 39개 중 8개와 그림자 11개가 빠져 있어서, DS를 들이기 전에도 `cn()`이 이 클래스를 색 클래스와 겹친다며 지울 수 있습니다.
   - 빠진 텍스트 스타일: `text-heading-7-medium`, `text-body-1-semibold`, `text-label-3-bold`, `text-label-3-medium`, `text-label-4-regular`, `text-caption-1-semibold`, `text-caption-3-bold`, `text-caption-3-medium`
   - 빠진 그림자: `shadow-drop-neutral-1`부터 `4`까지, `shadow-drop-primary-1`, `shadow-inner-neutral-1`부터 `4`까지, `shadow-inner-primary-1`, `shadow-pagination-num-hover`

   `APP_TEXT_STYLES`는 앱 텍스트 스타일 39개, `APP_SHADOWS`는 앱 그림자 12개 배열입니다. DS 배열과 함께 등록합니다.

   ```ts
   import { shadowUtilities, textStyleUtilities } from "@umc-product/design-tokens"
   import { extendTailwindMerge } from "tailwind-merge"

   const twMerge = extendTailwindMerge({
     extend: {
       classGroups: {
         shadow: [...shadowUtilities, ...APP_SHADOWS],
         "font-size": [...textStyleUtilities, ...APP_TEXT_STYLES],
       },
     },
   })
   ```

3. **CSS 불러오기**: `src/app/app.css` 맨 위 `@import "tailwindcss"` 바로 아래에 두 줄을 넣습니다. 앱 CSS는 모두 그 뒤에 둡니다.

   ```css
   @import "tailwindcss";
   @import "@umc-product/react/styles.css";
   @import "@umc-product/design-tokens/tailwind.css";
   @import "tw-animate-css";
   @import "shadcn/tailwind.css";
   @import "../styles/font.css";
   @import "../styles/color.css";
   @import "../styles/typography.css";
   @import "../styles/shadow.css";
   @import "../styles/custom.css";
   ```

   이 순서에서 겹치는 이름은 이렇게 됩니다.
   - 색: `app.css`의 `@theme inline`이 모든 import 뒤에 있어서 `--color-teal-*`, `--color-teal-gray-*`, shadcn 색을 DS 팔레트 초기화 뒤에 다시 등록합니다. `bg-teal-500`은 계속 앱 값입니다.
   - 텍스트 스타일: 같은 이름의 `@utility`는 한 규칙으로 합쳐지고, 뒤에 선언한 앱 값(크기, 굵기, 행간, 자간)이 이깁니다. DS가 더하는 font-family는 앱 `font-sans`와 같은 Pretendard입니다.
   - 그림자: 앱의 `@utility`가 DS 유틸리티 뒤에 나와서 앱 값이 이깁니다.

4. **Pretendard 중복 지우기**: `src/styles/typography.css` 1행의 Pretendard import를 지웁니다. DS `styles.css`가 같은 파일을 불러옵니다.

5. **기본 팔레트 33곳 바꾸기**: Tailwind 기본 팔레트는 앱 `@theme`에 없어서 DS 초기화로 사라지거나 DS 값으로 바뀝니다. 아래처럼 DS 클래스로 바꿉니다.

   | 지금                                         | 사용 | 1단계에서 생기는 일 | 바꿀 클래스                                            |
   | -------------------------------------------- | ---- | ------------------- | ------------------------------------------------------ |
   | `border-neutral-200`                         | 7    | 사라짐              | `border-neutral-weak-200`                              |
   | `text-gray-900`                              | 2    | 사라짐              | `text-neutral-default-900`                             |
   | `text-gray-700`                              | 1    | 사라짐              | `text-teal-grey-700`                                   |
   | `hover:text-gray-500`                        | 1    | 사라짐              | `hover:text-neutral-weak-500`                          |
   | `text-gray-400`, `placeholder:text-gray-400` | 4    | 사라짐              | `text-placeholder`, `placeholder:text-placeholder`     |
   | `border-gray-400/15`                         | 1    | 사라짐              | `border-teal-grey-400/15`                              |
   | `divide-gray-100`                            | 1    | 사라짐              | `divide-teal-grey-100`                                 |
   | `text-neutral-800`                           | 1    | 사라짐              | `text-neutral-strong-800`                              |
   | `bg-neutral-900/85`                          | 1    | 사라짐              | `bg-dimmed-strong`                                     |
   | `text-red-500`                               | 4    | DS 값으로 바뀜      | `text-error`                                           |
   | `text-red-400`, `hover:text-red-600`         | 2    | DS 값으로 바뀜      | 오류를 뜻하면 `text-error`                             |
   | `bg-red-50`, `border-red-200`                | 2    | DS 값으로 바뀜      | `bg-fill-error-weak-50`, `border-error-weak-200`       |

   위치는 아래 명령으로 찾습니다.

   ```bash

   ```

6. **새로 칠해지는 텍스트 스타일 확인**: 앱에 정의 없이 쓰던 네 이름이 DS 값으로 칠해집니다. `text-body-2-semibold`(2회), `text-body-3-semibold`(1회), `text-caption-1-regular`(3회), `text-heading-3-bold`(1회)입니다. 의도한 모양인지 화면에서 봅니다. `text-label-2-regular`(1회)는 DS에도 없어 계속 효과가 없습니다.

7. **화면 비교**: 주요 화면을 1단계 전후로 캡처해 비교합니다. 5, 6번 밖에서 달라진 곳이 있으면 `app.css`의 import 순서부터 확인합니다.

</Steps>

## 2단계: 화면 단위로 옮기기

손대는 화면부터 DS 클래스와 컴포넌트로 바꿉니다.

- 색은 semantic 클래스(`text-neutral-default-900`, `bg-fill-primary-weaker-50`)로 씁니다. 3단계 전까지 `teal-*` primitive는 앱 값이 이기므로 DS 문서의 값과 다릅니다.
- 아래 표의 ΔE는 CIEDE2000 색 차이입니다. 1 미만이면 사실상 같고, 2에서 5 사이는 나란히 두면 구분되며, 5를 넘으면 다른 색입니다. 2를 넘는 곳은 디자인 팀과 확인합니다.

### 토스트

앱은 zustand 스토어의 `addToast`를 225곳에서 부릅니다. 그중 `src/shared/lib/accessDenied.ts`는 라우트 `beforeLoad`에서, 즉 React 밖에서 부릅니다. DS `useToast()`는 Provider 안에서만 쓸 수 있으므로 스토어를 그대로 두고, 쌓인 토스트를 DS로 흘려보내는 브리지를 둡니다. 부르는 쪽 코드는 바꾸지 않습니다.

```tsx
import { ToastProvider, useToast } from "@umc-product/react"
import { type ReactNode, useEffect } from "react"

import { type ToastItem, useToastStore } from "@/shared/ui/toast/useToastStore"

function ToastBridge() {
  const toast = useToast()

  useEffect(() => {
    const drain = ({ toasts }: { toasts: ToastItem[] }) => {
      if (toasts.length === 0) return
      for (const item of toasts) {
        toast.show({
          message: item.message,
          color: item.color === "red" ? "error" : "primary",
          duration: item.duration,
          action: item.action,
        })
      }
      useToastStore.setState({ toasts: [] })
    }
    drain(useToastStore.getState())
    return useToastStore.subscribe(drain)
  }, [toast])

  return null
}

export function AppToastProvider({ children }: { children: ReactNode }) {
  return (
    <ToastProvider>
      {children}
      <ToastBridge />
    </ToastProvider>
  )
}
```

- `src/routes/__root.tsx`에서 앱 `<ToastProvider />`를 지우고 화면 전체를 `AppToastProvider`로 감쌉니다. 데스크톱 안내 화면 위에서도 토스트가 뜨는지 확인합니다.
- `variant`(deep, weak)와 `type`(time, notice)은 DS에 없어서 버려집니다. 기준 커밋에서 weak는 3회, notice는 5회 씁니다.
- 브리지가 그려지기 전에 쌓인 토스트(라우트 가드가 넣은 것)는 브리지가 처음 그려질 때 한꺼번에 보여 줍니다.

### 링크

DS의 `Header`, `SideNavigation`, `PageHeader`는 [LinkProvider](../../components/shell/link-provider/)에 등록한 컴포넌트로 링크를 그립니다. TanStack Router `Link`를 그대로 등록하면 두 가지가 어긋납니다.

- TanStack `Link`는 활성일 때 넘겨받은 `aria-current`를 자기 값으로 덮어씁니다.
- 기본 매칭은 상위 경로 링크까지 활성으로 봅니다. DS는 가장 긴 href 하나만 활성으로 칠하므로 강조가 두 곳에 생깁니다.

TanStack의 활성 판정을 정확히 일치로 좁히고 기본 `active` 클래스를 끄는 어댑터를 둡니다.

```tsx
import { Link } from "@tanstack/react-router"
import type { LinkComponentProps } from "@umc-product/react"

const EXTERNAL_HREF = /^(?:[a-z][a-z\d+.-]*:|\/\/)/i

export function AppLink({
  href,
  className,
  children,
  "aria-current": ariaCurrent,
}: LinkComponentProps) {
  if (EXTERNAL_HREF.test(href)) {
    return (
      <a href={href} className={className} aria-current={ariaCurrent}>
        {children}
      </a>
    )
  }
  return (
    <Link
      to={href}
      className={className}
      aria-current={ariaCurrent}
      activeOptions={{ exact: true, includeSearch: false }}
      activeProps={{}}
    >
      {children}
    </Link>
  )
}
```

`src/routes/__root.tsx`에서 화면 전체를 `<LinkProvider component={AppLink}>`로 감쌉니다. href에 쿼리나 해시가 필요해지면 문자열을 나눠 `search`, `hash`로 넘기도록 어댑터를 고칩니다.

## 3단계: 앱 정의 지우기

옮긴 화면이 충분히 쌓이면 앱이 따로 정의한 이름을 지웁니다.

1. 남은 사용처가 없는지 찾습니다. 패턴의 `teal-gray`를 다른 이름으로 바꿔 같은 방법으로 셉니다.

   ```bash
   rg -n --pcre2 '(?<![\w-])(?:[a-z0-9-]+:)*!?[a-z]+-teal-gray-\d+' src -g '!src/styles/**' -g '!src/app/app.css'
   ```

2. `app.css`의 `@theme inline`에서 `--color-teal-*`를 지웁니다. 남아 있는 `teal-*` 클래스는 DS 값으로 바뀌므로, [teal 표](#색-teal)에서 ΔE가 큰 300과 400을 쓰는 화면부터 확인합니다.
3. `--color-teal-gray-*`와 error, warning, success, chip, role 색 등록을 지웁니다.
4. `src/styles/typography.css`와 `src/styles/shadow.css`의 `@utility`를 지웁니다. 같은 이름으로 남아 있던 클래스는 [텍스트 스타일 표](#텍스트-스타일)의 "DS의 같은 이름" 값으로 바뀝니다.
5. `src/shared/lib/utils.ts`에서 `APP_TEXT_STYLES`와 `APP_SHADOWS`를 지웁니다.
